# Plan 6.2: Frontend Leave UI & Approvals

## Objective
Update the Employee Hub UI for leaves to support Half-Day applications and a "Pending Approvals" view for Managers, HR, and Admins.

## Context
- .gsd/SPEC.md
- Frontend/src/app/employee-management/page.tsx

## Tasks

<task type="auto">
  <name>Implement Half-Day / Full-Day Leave Forms</name>
  <files>Frontend/src/app/employee-management/page.tsx</files>
  <action>
    - Update the Leave Application form/modal to include a `leaveType` dropdown (`Full Day`, `Half Day - AM`, `Half Day - PM`).
    - If a half day is selected, optionally show `halfDayTime`.
    - Ensure it calls the `POST /api/employee-management/leaves` endpoint correctly.
  </action>
  <verify>tsc --noEmit</verify>
  <done>Users can apply for Half-Day and Full-Day leaves.</done>

<task type="auto">
  <name>Build Pending Approvals View</name>
  <files>Frontend/src/app/employee-management/page.tsx</files>
  <action>
    - Create a "Pending Approvals" sub-tab or view within the Leaves tab, visible if the user's role is Admin, Manager, or HR (mocked via local state for now since full Auth is in Phase 3).
    - Fetch pending leaves using `GET /api/employee-management/leaves/pending?role={userRole}`.
    - Add UI to Approve or Reject these leaves, hitting `PUT /api/employee-management/leaves/:id/status`.
    - Refactor the main leaves list to only show the user's "Own Leaves" by fetching `GET /api/employee-management/leaves?employeeId={userId}`.
  </action>
  <verify>tsc --noEmit</verify>
  <done>Approvers can see and action leaves routed to them.</done>
</task>

## Success Criteria
- [ ] Half-Day leaves can be successfully submitted.
- [ ] HR, Managers, and Admins can view and approve/reject leaves.
- [ ] UI correctly distinguishes between own leaves and pending approvals.
