## Microsoft OAuth SSO Integration Plan

Per `TECHNICAL_SPECIFICATIONS.md`:

- Use `@azure/msal-node` (backend) and `@azure/msal-react` (frontend) packages
- Map incoming Azure Entra ID `oid` / `userPrincipalName` to `Employee.microsoftId` and `Employee.email`
- Authenticated requests pass a JWT Bearer token containing RBAC role (`Admin`, `Engineer`, `Supervisor`, `Operator`, `Viewer`)
- `Employee.microsoftId` field already exists in `schema.prisma` — ready to receive the Azure OID

## AWS EC2 Cloud Deployment Plan

Per `TECHNICAL_SPECIFICATIONS.md`:

1. Provision **AWS EC2 instance** (Ubuntu / Amazon Linux 2023)
2. Install Node.js runtime and **PM2** process manager
3. Update `DATABASE_URL` in `.env` to point to PostgreSQL (AWS RDS or Supabase)
4. Run `npx prisma db push` on EC2 to migrate schema
5. Start server: `pm2 start dist/server.js`

## Notable Absences (Technology Gaps)

| Missing | Impact |
|---------|--------|
| Test framework (Jest, Vitest, Playwright) | Zero tests of any kind — no safety net for changes |
| API client library (Axios, React Query, SWR) | Manual `fetch()` boilerplate repeated on every page — no caching, retries, or loading state management |
| State management library (Zustand, Redux Toolkit) | `useState` sprawl in 2,000+ line page files; no cross-page state sharing |
| Shared type package (`packages/types`) | Frontend/Backend type drift risk — API shape changes require manual sync on both sides |
| Input validation (Zod, express-validator) | No request body validation or sanitisation on any route |
| Authentication library (NextAuth, Passport, MSAL) | No login, sessions, JWT validation, or RBAC enforcement |
| Logger (Winston, Pino) | Only `console.error` / `console.log` — no structured logging, no log levels, no log files |
| Environment variable validation (Zod, `envalid`) | No startup check for required env vars — silent misconfiguration failures |
| Error boundary (React `ErrorBoundary`) | Unhandled fetch failures can cause silent UI blank screens |
| CORS origin allowlist | `app.use(cors())` is fully open — any origin can call the API |
